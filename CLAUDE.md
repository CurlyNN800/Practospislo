# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **6000.3.9f1** (Unity 6), URP 17.3, XR Interaction Toolkit 3.3 VR horror/shooter ("Cursed Mansion"). There is no CLI build, lint or test setup: compiling, running and building all happen in the Unity Editor. `com.unity.test-framework` is installed, but the repo has no tests or `.asmdef` files, so all game code compiles into `Assembly-CSharp` / `Assembly-CSharp-Editor`. `*.csproj` / `*.sln` are generated by Unity and gitignored.

Code comments and log messages are written in Russian. Keep that convention.

## Where the code lives

- `Assets/CursedMansion/Scripts`: main game code (namespace `CursedMansion`). Put new gameplay code here.
- `Assets/CursedMansion/Editor`: editor tooling under the **`CursedMansion/…` menu** (`MVP/`, `Scene/`, `AI/`, `Debug/`). These menus set up scenes (portals, spawn points, finale triggers, grabbables, passenger ride, NavMesh bake, furnishing), so scene setup is done through code rather than by hand-editing YAML.
- `Assets/Scripts`: older, mostly global-namespace scripts (menus, doors, `EnemyAI`/`EnemyHealth`, notes). Some class names don't match their file names (e.g. `MenuController.cs` → `DeathSceneLoader`, `Settings.cs` → `MenuManager`, `SceneChanger.cs` → `VRSceneChanger`, `NoteInteraction.cs` → `NoteDisplay`). Unity needs a MonoBehaviour's class name to match its file name to attach it to objects, so check before relying on these.
- `Assets/VRFPS Kit/Scipts` (the folder name really is misspelled): third-party VR firearm kit (namespace `VRFPSKit`): `Firearm`, `Magazine`, `Cartridge`, `Damageable`, `Player`, hand poses, XR sockets. Game code builds on `Damageable` / `Player` from this kit.
- Asset packs, not project code: `Flooded_Grounds`, `EasyRoads3D`, `Blink`, `VolumetricLines`, `Asset Packs`, `Samples/XR Interaction Toolkit`, `TutorialInfo`.

## Runtime architecture (CursedMansion)

The game is split into scenes, and most runtime wiring is set up from code rather than placed in scenes:

- **`GameLifetimeHooks`** uses `[RuntimeInitializeOnLoadMethod]` to subscribe to `SceneManager.sceneLoaded`. On every scene load it:
  - creates the `GameProgress` singleton if it is missing;
  - applies any pending spawn;
  - runs `SceneGrabbablesBootstrap.ApplyAll()`;
  - for the `Road` scene only, adds `RoadRuntimePack` and `RoadPathSceneTransition` and auto-mounts the player into `VrPassengerRide`.

  When a behaviour is "missing" from a scene, check here first.
- **`GameProgress`** (`DontDestroyOnLoad`) tracks the story state: `GamePhase` (OpeningRoad → MansionExterior → MansionInterior → EndingRoad) and `FinaleOutcome` (Victory / Defeat). In `Awake` it adds the global components `PlayerDeathToGameProgress`, `PlayerDamageVfx`, `ExtraMagazinesOnTables` and `LightSourceVisuals`.
- **Scene transitions** always go through `SceneFlow.LoadX(spawnId)` → `SceneTransitionRunner.TransitionTo`. This does a fade via `ScreenFade`, then `SceneTransfer.PreparePlayerForLoad()` (unmounts the ride and unparents the `XROrigin`), then loads the scene. After the load, `SceneTransfer.ApplyPendingSpawn()` places the player:
  1. at the `SceneSpawnPoint` matching the spawn id;
  2. otherwise at the default `SceneSpawnPoint`;
  3. otherwise at a `CM_Spawn_<id>` or `PlayerSpawn` GameObject.

  `SceneTransitionRunner` ignores new requests while a load is in progress (`s_Loading`).
- **Scene names** are constants in `GameScenes` (`Road`, `HouseScene`, `Interior`, `InsideHouse`) and must match the `.unity` file names and the Build Settings. Currently only `Assets/Scenes/SampleScene.unity` is committed and listed in Build Settings. Keep this in mind before assuming the other scenes exist.
- **Player detection:** use `SceneTransfer.IsPlayerCollider` (XROrigin, CharacterController, `Player` tag, or a root named "VR Player") instead of ad-hoc tag checks.
- **The road intro** is driven by `SimpleWaypointVehicle` / `VehiclePathAuthor` (authored with `VehicleSplineToolWindow`). The player rides along via `VrPassengerRide`, and `RoadToHouseOnPathComplete` / `RoadPathSceneTransition` move the game to `HouseScene` when the path ends.

## Git

Unity `.meta` files must be committed together with their assets. `Library/`, `Temp/`, `Logs/` and `UserSettings/` are ignored.
